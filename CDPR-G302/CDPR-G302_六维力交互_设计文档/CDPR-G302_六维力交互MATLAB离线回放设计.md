# CDPR-G302 六维力交互 MATLAB 离线回放设计

## 1. 目标与边界

本功能用于阶段 B、阶段 C 及后续实机阶段的运行后检查。Qt 完成实时控制与原始
数据记录，MATLAB 根据八轴同帧 Trace 反馈重建绳长、计算正运动学，并绘制虚拟
动平台运动动画，以便直观检查“外力—期望末端运动—八轴执行—虚拟实际末端
运动”是否一致。

Qt 与 MATLAB 必须完全解耦：

- Qt 不调用 MATLAB Engine，不启动 MATLAB 进程，也不配置 MATLAB 路径；
- Qt 只输出标准 CSV 和 JSON 文件；
- 操作者自行打开 MATLAB，手动运行回放入口；
- MATLAB 结果不回写 Qt，也不参与任何在线控制或安全判定；
- MATLAB 计算再慢也不得影响控制周期、Trace 读取或停车逻辑。

空转回放得到的是基于编码器反馈和假定绞盘/绳索连接关系重建的**虚拟实际
位姿**。它可以验证八轴同步、方向映射、换算关系和运动学一致性，不能替代真实
绳索张力、弹性、打滑、结构变形和动捕实测结果。

## 2. 代码归属

在 `CDPR-G302` 工程内新建并独立维护：

```text
CDPR-G302/
  matlab_offline_replay/
    README.md
    replay_force_interaction_run.m
    io/
    model/
    analysis/
    visualization/
    tests/
```

根目录现有 `MATLAB代码/CDPR_dynamics_solve/G302_current` 只作为算法、坐标变换
和绘图实现的参考来源：

- 新模块运行时不得依赖该目录，也不得通过相对路径调用其中脚本；
- 不直接修改旧 MATLAB 项目，避免旧仿真和当前实机回放互相污染；
- 只迁移经过核对的最小功能，并在新文件注释中标明参考来源；
- 当前 Qt 冻结参数和运行数据是回放的唯一事实来源，旧
  `fun_cdpr_params_G302.m` 不能作为当次实验参数来源；
- 旧 `G302.m` 中的动力学积分方法不进入本回放链。回放只重建已经发生的八轴
  执行结果，不重新运行 RK4 或 Newmark 来替代 Qt 记录。

## 3. 现有基础与缺口

### 3.1 已有数据

当前 `force_interaction_run_v11` CSV 已记录：

- 主机单调时间、Trace 序号、Trace 时间和有效标志；
- Newmark 期望位姿、速度和加速度；
- 八绳期望长度和相对电机角；
- 八轴参考位置、速度命令、同帧 Trace 位置和速度；
- F/T 原始工程值、软件零点、滤波前后质心力旋量；
- 工作空间余量、停车距离、交互/制动分段及停车原因；
- 周期计算、硬件 API 和完整周期耗时。

现有 C++“验算最近运行”已经可以逐个有效 Trace 帧执行正运动学并生成
`_kinematic_analysis.csv`。该结果用于与 MATLAB 独立实现交叉核对，不作为
MATLAB 的输入捷径。

### 3.2 当前缺口

运行 CSV 尚未持久化正运动学复算所需的全部冻结参数。当前 C++ 验算依赖程序
会话内存中的运动学上下文，程序关闭后不能保证按原条件重建。缺少的主要内容为：

- 本次运行的实际出绳点和平台连接点；
- 轴号、绳索号、从站号和实体绞盘的映射；
- 电机旋转方向、收放绳符号及单位换算；
- 初始 Trace 基准、初始绳长和初始末端位姿；
- 本次冻结的绞盘、排绳和滑轮模型参数；
- 明确的长度、角度、姿态和时间约定。

因此需要为每次运行增加参数 JSON，而不是让 MATLAB 从当前 UI 或旧参数脚本
猜测实验参数。

## 4. 文件级数据接口

每次阶段 B/C/D 运行形成以下文件：

```text
force_interaction_stage_c_YYYYMMDD_HHMMSS_mmm.csv
force_interaction_stage_c_YYYYMMDD_HHMMSS_mmm_replay_config.json
```

两个文件使用相同的运行 ID。JSON 内保存 CSV 文件名、CSV schema 和参数 schema，
MATLAB 加载时必须核对三者一致。CSV 不复制第二份，避免大文件重复占用磁盘。

MATLAB 结果写入独立目录：

```text
force_interaction_stage_c_..._matlab_replay/
  replay_result.mat
  pose_history.csv
  summary.json
  trajectory_overview.png
  tracking_error.png
  virtual_platform_replay.mp4      # 用户选择生成时才创建
```

原始 CSV 和 Qt 导出的 JSON 始终只读，MATLAB 不覆盖源文件。

## 5. Qt 导出职责

### 5.1 导出时机

运行准备成功时，Qt 已冻结本次运动学、执行器和安全参数。记录器创建运行 CSV 后，
立即使用冻结快照生成同名 JSON。JSON 写入不进入控制线程，采用临时文件加原子
替换；失败只记录导出故障，不得阻塞运动控制或伪装成已成功导出。

六维力交互页顶部现有“验算最近运行”旁增加：

- `导出最近运行回放配置`：为最近一次完整运行生成或重新生成 JSON；
- `打开记录目录`：只打开文件夹，不启动 MATLAB。

正常情况下 JSON 已随运行自动生成，按钮用于补导出和人工确认，不重新写一份
大 CSV。

### 5.2 Qt 明确不做的事情

- 不生成 `.m` 文件；
- 不复制或修改旧 MATLAB 工程；
- 不执行正运动学动画；
- 不查找 `matlab.exe`；
- 不等待 MATLAB 结果；
- 不将 MATLAB 结果用于运行准入或安全保护。

## 6. `replay_config.json` 内容

JSON 顶层至少包含以下分组。

### 6.1 身份与版本

- `schema`: `cdpr_g302_matlab_replay_config_v1`；
- `run_id`、`created_at`、`csv_file`、`csv_schema`；
- `stage`、力源类型；
- `kinematic_template`：例如 G302；
- `actuator_template`：G302 原执行器或临时增量编码器 8 轴；
- `control_period_us`、`trace_period_us`；
- 配置摘要或哈希，用于检测 CSV/JSON 配错。

运动学模板和执行器模板必须分开保存。临时电机只改变执行器换算，不得把
G302 几何参数误标为“临时样机几何”。

### 6.2 坐标与单位约定

- 长度：JSON 几何统一使用 `mm`；MATLAB 内部可在入口统一转为 `m`；
- 角度：统一使用 `rad`；
- 位姿顺序：`[x,y,z,rx,ry,rz]`；
- 局部点到全局点：`T = Trans(x,y,z) * Rz(rz) * Ry(ry) * Rx(rx)`；
- 出绳点位于全局系，平台连接点位于质心局部系；
- 电机位置单位、脉冲单位和换算符号分别声明，禁止只凭列名猜单位。

### 6.3 几何参数

- `base_anchor_global_mm[8][3]`；
- `platform_attachment_local_mm[8][3]`；
- `pulley_radius_mm`；
- `cable_length_model`：直线段或当前 Qt 实际使用的滑轮长度模型；
- `initial_pose_mm_rad[6]`；
- `reference_cable_length_mm[8]`；
- 几何硬边界及8个平台边界检查点。

不能直接使用旧 MATLAB 参数。当前 Qt G302 连接点、上下层出绳点和旧
`fun_cdpr_params_G302.m` 中的简化长方体/顶层锚点模型不同，必须以冻结 JSON
为准。

### 6.4 八轴映射与执行器参数

每根绳索保存一条明确记录：

- `cable_index`、界面逻辑轴号、EtherCAT 轴号、从站号；
- 对应出绳点索引和平台连接点索引；
- `motor_hardware_direction_sign`；
- 电机正转对应收绳还是放绳；
- `pulse_per_unit`、`unit_per_radian`；
- 运行起点绝对 Trace 位置和安全相对零位；
- `cable_motor_scale_rad_per_mm`；
- 绞盘半径、排绳螺距、投影长度、初始轴向偏移及补偿开关；
- 初始轴向偏移是否有效及其来源。

MATLAB 必须逐轴使用该表，不能假设 CSV 的轴0天然等于 MATLAB 的绳索1。

### 6.5 运行与安全上下文

- 计划最长运行时间；
- 是否仅平动；
- 工作空间上下界；
- 减速度、附加安全余量和急停线；
- 末端速度/加速度限制和轴速度限制；
- 是否启用绞盘行程、跟随误差及其他保护；
- 终态、试验有效标志和停车原因（运行结束后可补写终态摘要）。

## 7. MATLAB 回放流程

统一入口设计为：

```matlab
result = replay_force_interaction_run(replay_config_json);
```

无参数启动时，文件选择框应扫描工程 `build` 下的六维力交互记录目录，
默认定位并选中最新的 `_replay_config.json`，而不是停留在 MATLAB 源码目录。

入口根据 CSV 自动寻找同名 JSON，完成以下步骤。

### 7.1 加载和一致性检查

1. 读取并验证 JSON schema、CSV schema、运行 ID 和文件名；
2. 检查8根绳索的映射、方向、单位和初始参考是否完整；
3. 检查 CSV 所需列是否存在；
4. 只接受 `trace_valid=1`、八轴位置完整且 Trace 序号严格递增的记录；
5. 报告无效行、序号断裂、重复帧和记录丢弃，不静默插值伪造反馈。

### 7.2 选择回放区间

默认分析整个有效记录，但动画默认播放“有效交互段”，即：

- 从首个可靠同帧八轴反馈开始；
- 到 `interaction_segment` 由交互切换为安全制动之前结束；
- 若先出现故障或立即停止，则截止到最后一帧完整反馈；
- 提供 `include_controlled_stop=true` 选项，用于观察受控停车过程；
- 图中标出预警、停车触发、急停和记录终止时刻。

这样既能观察用户关心的停车前运动，也不会丢失用于检查制动行为的数据。

### 7.3 电机位置到绳长

优先读取 `axis_safety_relative_trace_position_0...7`。每帧按 JSON 中逐轴参数执行：

```text
相对板卡位置 → 电机相对角度 → 绞盘/排绳补偿位移 → 实际绳长
```

绳长基准为本次冻结初始位姿计算所得的 `reference_cable_length_mm`。方向符号、
临时模板脉冲当量和绞盘补偿必须与 Qt 相同。不得使用各轴独立延迟将八根绳索
移动到八个不同物理时刻；平台位姿始终由同一 Trace 帧内的八轴状态共同决定。

### 7.4 正运动学

- 对每个有效同帧八轴样本执行一次正运动学；
- 第一帧使用冻结初始位姿，后续帧使用上一帧解作为初值；
- 使用8根绳索进行超定约束最小二乘，同时记录 RMS/最大绳长残差；
- 使用与 Qt 相同的姿态顺序、长度模型和几何边界；
- 当前实验虽然只施加三维力、期望姿态保持不变，正运动学仍求完整六维位姿；
  非期望转动是需要观察的误差，不能通过强制锁死姿态将其隐藏；
- 可额外提供“姿态固定复算”作为诊断对照，但不得替代完整六维主结果。

### 7.5 统计与动画

正运动学对全部有效反馈帧计算，不因动画帧率而抽样。动画单独按默认30 fps
重采样，以降低绘图开销。输出至少包括：

- Newmark 期望轨迹和 Trace 正运动学轨迹；
- 三轴平移误差、三轴非期望转动；
- 八绳长度及绳长残差；
- 正运动学收敛率和失败帧；
- 最大/均方根平移误差、姿态误差；
- 工作空间最小余量和停车触发点；
- 机架、动平台、8根绳索和质心历史轨迹动画。

视频是可选输出；交互式动画和数值结果必须不依赖视频编码器。

## 8. 对旧 MATLAB 代码的复用原则

可参考并重构：

- `plot_trajectory_G302.m` 的机架、平台、绳索和 MP4 绘制方式；
- `plot_init_spaceTrj_G302.m` 与 `plot_update_spaceTrj_G302.m` 的图元初始化和更新；
- 现有齐次变换、正逆运动学和绳索干涉检查中的数学关系；
- `G302_static_structure_diagram.m` 的静态几何显示。

不得直接沿用：

- `fun_cdpr_params_G302.m` 中与当前 Qt 模板不一致的固定几何值；
- `G302.m` 的动力学时间推进作为实测回放依据；
- 旧传感器安装关系、质量惯量或坐标轴方向去覆盖本次 JSON；
- 旧脚本中隐含的绳索顺序、单位和电机方向假设。

新模块中的几何绘图函数只接受显式参数结构，不读取基础工作区全局变量。

## 9. 与现有 C++ 后验算的交叉验证

MATLAB 模块完成后，先选择已有阶段 B/C 记录进行双实现对照：

1. Qt 对同一原始 CSV 执行现有“验算最近运行”；
2. MATLAB 从原始 CSV 和 JSON 独立完成电机角—绳长—正运动学；
3. 比较两端逐帧绳长、位姿、RMS残差、最大残差和有效帧数量；
4. 首帧应回到冻结初始位姿，静止段不得出现持续漂移；
5. 人工构造单轴正负位移，确认八轴方向和绳索编号没有置换；
6. 确认MATLAB默认截止帧与CSV中的交互段/停车事件一致；
7. 差异超过约定数值容差时先停止使用动画结论，定位单位、姿态顺序、轴映射、
   滑轮或绞盘模型差异。

C++结果用于交叉检查，但MATLAB不能直接读取 `_kinematic_analysis.csv` 作为自己的
实际位姿输入，否则无法形成独立验证。

## 10. 实施顺序

1. **冻结数据协议**：定义 JSON v1、单位、姿态和轴映射字段；
2. **Qt 参数导出器**：从阶段B/C实际冻结上下文生成同名JSON，增加补导出与打开
   目录按钮；不改高频控制路径；
3. **MATLAB 加载器**：读取CSV/JSON并完成完整性检查；
4. **换算与正运动学**：逐帧重建绳长和六维虚拟实际位姿；
5. **分析输出**：生成MAT、结果CSV、摘要JSON和静态曲线；
6. **动画模块**：复用旧项目绘图思路，但使用新模块自己的参数化图元；
7. **双实现验收**：用现有多次阶段B/C记录与C++后验算交叉比较；
8. **实机扩展**：阶段D继续使用相同文件协议，后续再加入动捕实测位姿作为第三条
   对照轨迹，无需改动Qt—MATLAB解耦边界。

## 11. 第一版完成标准

- Qt 在不安装MATLAB的电脑上仍可正常运行和导出；
- 导出动作不进入实时线程，不造成控制耗时尖峰；
- 任一运行CSV离开原程序会话后，仍可凭同名JSON完整复算；
- MATLAB工程不添加根目录旧MATLAB文件夹到运行路径；
- 每个有效同帧八轴样本均参与正运动学，动画降采样不影响数值统计；
- 能选择仅播放有效交互段或连同受控停车段；
- 能直观看到期望轨迹、虚拟实际轨迹和非期望姿态；
- MATLAB与现有C++后验算在统一模型下结果一致，并明确报告失败帧和残差；
- 原始CSV和JSON保持只读，可重复生成相同结果。

## 12. 当前实现状态（2026-09-17）

- Qt 已增加独立回放参数导出器；阶段 B/C 运行结束后自动在原始 CSV
  旁生成同名 `_replay_config.json`，也可在六维力交互页手动重导出并打开记录目录。
- JSON 参数取自本次准备阶段冻结的运动学、绞盘、工作空间、Trace周期、
  延迟标定和执行器映射，不从旧 MATLAB 模型或运行结束后的可变 UI 值猜测。
- 已建立独立 `matlab_offline_replay` 工程，可读取 CSV/JSON、按全部有效
  同帧八轴 Trace 重建绳长、逐帧求六自由度正运动学、输出统计/曲线并播放动画。
- MATLAB 工程不引用根目录旧《MATLAB代码》，Qt 也不检测或调用 MATLAB。
- Qt 工程已通过 Qt 6.8.1/MSVC2022 Debug 完整构建；MATLAB R2022a 脚本已通过
  `checkcode` 静态检查。实测交叉验收需在下一次阶段 B/C 运行自动生成 JSON 后，
  对同一次记录分别运行 C++“验算最近运行”和 MATLAB 回放再比较结果。
