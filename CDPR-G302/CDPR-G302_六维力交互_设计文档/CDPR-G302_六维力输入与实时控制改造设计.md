# CDPR-G302 六维力输入与实时控制改造设计

## 1. 文档目的

本文说明如何在 `CDPR-G302` 中保留现有末端遥控的八轴在线速度执行链，
把“人工方向输入产生末端运动”扩展为：

```text
模拟六维力 / 真实六维 F/T Trace
→ 力旋量校正与坐标变换
→ 纯惯性 Newmark-β 单步
→ 末端期望位姿、速度、加速度
→ 补偿运动学与八绳逆运动学
→ 八轴速度前馈（位置PID修正接口暂留，近期默认关闭）
→ 同帧 Trace 安全校验
→ 八轴在线速度命令
```

本文既说明总体改造路线，也记录实际完成进度。阶段 A 的纯软件数学模块和
“只计算”验证入口已经写入 `CDPR-G302`；阶段 B 已完成模拟力八电机空载基本链路
实测，具备进入阶段 C 的条件；阶段 C（真实 F/T 下八电机空转）已按本文计划完成
首版代码接入并通过构建与静态审查，下一步是实机零力/小力空载验收。阶段 D
（接绞盘、绳索和真实平台）尚未开始。

## 2. 已确认边界与待定参数

### 2.1 已确认

- 目标工程是 `CDPR-G302`，不是把它迁入 `cdpr_control`。
- 动力学模型采用纯惯性自由刚体，不加入回中刚度或人为阻尼。
- 实时力输入在一个模型周期内使用当前已取得样本，按 ZOH 保持；不得使用
  未来样本做无延迟 FOH。
- 首阶段可使用模拟六维力；真实传感器接入后由控制卡 Trace 取得六个通道。
- 当前样机的软件验证和后续力交互开发统一选择“控制界面”的 `G302` 模板；
  阶段 A 在非 G302 模板下拒绝启动，避免混用 ACC 几何和边界。
- 八轴使用同一组 PID 参数，但各轴必须保存独立的积分、上次误差和上次命令
  状态，不能共用一份 PID 动态状态。
- 近期阶段B～D调试只使用开环速度前馈，位置PID默认关闭且不作为阶段B验收项；
  PID控件和独立状态仅作为后续研究位置修正效果的暂留功能。
- 现有遥控链的同帧 Trace 校验、批量在线变速、会话令牌、停机邮箱及硬件线程
  串行访问应尽量保留。

### 2.2 必须保持“未配置”的项目

以下内容在实物尺寸或对象定义确定前不得填入猜测值：

1. 传感器正负方向约定 `sensorSign`；
2. 六个 F/T Trace 对象在雷赛 Trace 接口中的最终索引/子索引表达；
3. 六个对象与 `Fx、Fy、Fz、Mx、My、Mz` 的实机读取顺序和正负方向。

根据 `六维力传感器PDO信息.png`，传感器 TxPDO 数据契约已经明确：

| 对象 | 含义 | 类型 | 工程值换算 |
|---|---|---|---|
| `0x4000:00` | `Fx` | `DINT` | `raw / 10000` N |
| `0x4001:00` | `Fy` | `DINT` | `raw / 10000` N |
| `0x4002:00` | `Fz` | `DINT` | `raw / 10000` N |
| `0x4003:00` | `Mx` | `DINT` | `raw / 10000` N·m |
| `0x4004:00` | `My` | `DINT` | `raw / 10000` N·m |
| `0x4005:00` | `Mz` | `DINT` | `raw / 10000` N·m |
| `0x4006:00` | StatusCode | `UDINT` | 状态字，位定义待厂家资料确认 |
| `0x4007:00` | SampleCounter | `UDINT` | 1 count = 1 ms |
| `0x4008:00` | Temperature | `DINT` | `raw / 10` °C |

RxPDO `Control Code` 为 `DINT`；其 bit0 的上升沿使传感器清零。正式程序默认只读，
在尚未明确厂家清零行为、保持时间和故障恢复语义前，不自动写该位。

下位机PDO界面显示上述对象统一映射在 `TxPDO 1 (0x1A00)` 中，每项长度为4字节。
从站号随六维力交互执行器模板解析：原G302整机链为8电机 `1001~1008`、张力
变送器 `1009`、六维F/T `1010`；临时8轴调试链没有张力变送器，六维F/T仍为
`1009`。雷赛Trace应使用 `data_type=19`、相应对象索引、`sub_index=0`、当前模板
解析出的 `slave_id`、`data_bytes=4`。开始F/T监测及准备阶段C前，程序读取从站总数、
核对8个电机的实际节点地址及相关从站OP状态；原G302要求10站，临时模板要求9站。
此前日志中的
`16386=0x4002`对应Fz，`16384=0x4000`对应Fx；两条完全相同的`0x4000:00`
表示当时重复加入了Fx，并不是两个不同通道。现有工程 `0x6000:01...` 映射属于
SBT908E张力采集模块，不能套用到本六维F/T。

对象地址已经明确，但正式启用前仍要逐项核对
`dmc_trace_get_config_object()`读回，并用单方向加载试验确认通道符号；地址明确
不等于方向和安装正负号已经验收。

传感器受力/测量参考点的位置已经实测：它位于正二十面体几何中心正上方
`325.48 mm`。以动平台局部系 `E` 的原点作为几何中心、`+Z_E` 表示正上方，
且传感器坐标系三轴与动平台局部坐标系三轴完全同向。代码采用：

```text
R_ES = I
r_ES_E = [0, 0, 0.32548]^T m
```

当前将该实测点作为传感器坐标系 `S` 的测量参考原点；若传感器手册给出的
六维力矩参考原点与该受力点不同，实物标定时必须按两点之间的位移修正。

配置文件中应使用 `null`、空数组或显式 `configured=false` 表示其余未知项目，
不能用索引 0 等“看似可运行”的默认值代替。已知的单位旋转和力臂不得再回退
为零矩阵或零位矢。真实 F/T 模式在任一必要项目未配置时必须保持不可启动；
模拟力模式不受这些未知项阻塞。

## 3. 六维力坐标链

### 3.1 坐标系

- `G`：CDPR 全局坐标系；
- `E`：动平台局部坐标系，原点位于动力学使用的动平台质心；
- `S`：六维力传感器坐标系，原点位于传感器测量参考点。

原始传感器力旋量定义为：

```text
W_S = [F_S; M_S] = [Fx, Fy, Fz, Mx, My, Mz]^T
```

在扣除本次运行零漂 `b_S` 并应用方向约定后：

```text
F_S' = sensorSign · (F_S - b_F)
M_S' = sensorSign · (M_S - b_M)
```

从传感器坐标系变换到动平台质心局部坐标系：

```text
F_E = R_ES · F_S'
M_E = R_ES · M_S' + r_ES_E × F_E
W_E = [F_E; M_E]
```

当前实测安装关系为 `R_ES=I`，所以 `F_E=F_S'`，传感器原点处力矩也无需
旋转；但从传感器原点平移到平台质心所产生的 `r_ES_E × F_E` 仍不能省略。

其中 `r_ES_E` 是“从动平台质心指向传感器原点”的向量，在 `E` 系表达。
交叉项不能省略；否则只要力的作用点不在质心，质心处力矩就会计算错误。

代入当前实测力臂 `r_ES_E=[0,0,0.32548]^T m`，若
`F_E=[F_x,F_y,F_z]^T`，则：

```text
r_ES_E x F_E = [-0.32548 F_y, 0.32548 F_x, 0]^T N*m
```

因此沿局部 `X/Y` 方向的力即使传感器自身力矩读数为零，也会在动平台质心处
分别产生 `+Y/-X` 方向的附加力矩；沿局部 `Z` 方向的力不产生该平移力矩。

若记录或显示需要全局力旋量，可使用当前动平台姿态 `R_GE`：

```text
F_G = R_GE · F_E
M_G = R_GE · M_E
```

当前 Newmark 模块直接接收质心处、平台局部坐标系表达的 `W_E`，但平动与
转动的内部坐标约定不同：平动力在动力学内部用 `R_GE` 转到全局系后求全局
线加速度；力矩保留在平台局部系，与局部惯量矩阵和局部角速度共同求角加速度。
因此不是“六个分量先全部转到全局系再求解”。`W_G` 主要用于诊断、绘图或
其他明确要求全局表达的算法，避免重复旋转和误用惯量坐标系。

上述关系与 MATLAB 文件
`MATLAB代码/CDPR_dynamics_solve/G302_current/transform_sensor_wrench_to_ee.m`
一致；其中现有 `fun_cdpr_params_G302.m` 的安装参数仅是历史计算值，不能直接
当作当前实物标定结果。

## 4. 数据接口与模块职责

### 4.1 公共数据帧

已在 `pose_control_module/forceinteractiontypes.h` 中建立不依赖 UI 和板卡 SDK
的公共数据类型，其职责等价于：

```cpp
struct FrameStamp {
    quint64 traceSequence;
    qint64 traceTimeUs;
    qint64 hostReceiveTimeUs;
    bool valid;
};

struct WrenchSample6D {
    FrameStamp stamp;
    std::array<double, 6> value;
    WrenchCoordinate coordinate;
    bool valid;
};

struct EndpointDesiredState {
    FrameStamp stamp;
    std::array<double, 6> pose;
    std::array<double, 6> twist;
    std::array<double, 6> acceleration;
    bool valid;
};
```

所有六维力、末端状态、八轴命令和反馈都携带同一周期身份，禁止把不同 Trace
帧或不同控制周期的数据拼成一帧。

### 4.2 力输入接口

已增加统一的 `IWrenchSource`，使动力学层不关心数据来自 UI 还是硬件：

- `SimulatedWrenchSource`：常值、脉冲、正弦或预编译公式；
- `TraceFtWrenchSource`：接收硬件层解码后的六通道同帧数据；
- 后续若增加文件回放，只新增输入实现，不改 Newmark 和控制器。

模拟输入与未来真实 F/T Trace 采用同一语义：均表示传感器测量参考点、传感器
坐标系 `S` 下的原始六维力旋量。两者都必须经过同一个 `WrenchTransformer`，
使用唯一的实测安装关系 `R_ES=I`、`r_ES_E=[0,0,0.32548]^T m`，再把质心处
平台局部力旋量送入 Newmark。不得再保留“模拟量已经位于质心、可以绕过安装
变换”的第二条路径。

阶段 A 提供“仅平动调试”开关。该开关仍先执行完整安装变换和 `r×F` 计算，
随后才将质心处 `Mx/My/Mz` 清零；它只用于前期隔离转动因素，不能代表正式
六自由度模型。

### 4.3 安装变换模块

已增加独立 `WrenchTransformer`：

- 输入：去零漂后的 `W_S`、实测 `R_ES=I`、实测
  `r_ES_E=[0,0,0.32548]^T m`、`sensorSign`；
- 输出：质心处平台局部力旋量 `W_E`，可选输出 `W_G`；
- 只做确定性的数学变换，不读取 UI、Trace 或全局变量；
- 配置无效时返回明确错误，不输出全零有效帧。

可参考 `cdpr_control/cdpr/CdprForceInput.*` 的数据契约，但迁移到
`CDPR-G302` 时应重新适配命名空间、配置体系和现有线程模型，不能直接让两个
工程相互包含源文件。

### 4.4 Newmark-β 模块

已增加独立、可单元测试的纯惯性 `CdprDynamics`：

- 输入：当前有效 `W_E`、固定模型步长 `T_c`；
- 状态：末端位姿、速度、加速度；
- 输出：下一控制格点的 `EndpointDesiredState`；
- `β=0.25、γ=0.5`，不加入回中刚度；
- 每次启动由可信初始位姿重置，运行过程中只有控制线程能够修改内部状态。

可审查并迁移 `cdpr_control/cdpr/CdprDynamics.*`，同时保留其静止、恒力、
恒力矩、姿态奇异性和不收敛测试。

## 5. 对现有遥控架构的改造方式

### 5.1 保留的部分

保留以下已经验证过的机制：

- `ControlWorker` 的会话互斥、停机邮箱和调度入口；
- HardwareThread 对所有雷赛 API 的独占串行访问；
- 同一硬件任务内“读 Trace → 校验 → 下发八轴速度”的复合操作；
- 首次非零速度使用 `dmc_vmove`，运行期使用
  `dmc_change_speed_unit`；
- 八轴统一限速比例、加速度约束、软件行程和状态字检查；
- 命令成功后才提交运动学候选状态的事务式处理。

### 5.2 不直接复用的部分

`EndpointRemoteInputSupervisor` 的方向按键、50 ms 心跳和 X56 轮询只属于人工
遥控，不能放进六维力控制周期。`EndpointRemoteControl` 当前还把方向语义、
末端速度生成、边界检查、运动学和命令规划集中在一个类中，且主要是速度前馈，
不应直接改成读取六维力。

应新增 `EndpointForceInteractionControl`，并逐步抽取一个遥控和力交互共同使用
的八轴执行层：

```text
末端期望状态提供者
  ├─ 遥控提供者：方向 → 末端速度/位姿
  └─ 力交互提供者：六维力 → Newmark → 末端状态
                ↓
共同的边界/补偿运动学/八轴闭环/命令提交层
                ↓
HardwareInterface
```

首轮实现可以不立即重写旧遥控类，但六维力控制不得复制一套新的雷赛 API 调用
链；应调用同一个批量在线速度硬件入口。

### 5.3 八轴闭环

Newmark 输出经过补偿运动学得到八轴期望位置和速度。每轴命令为：

```text
v_cmd,i = Kff · v_ref,i
          + Kp · e_i
          + Ki · integral(e_i)
          + Kd · derivative(e_i)
```

进入阶段 B 前，必须先对当前执行器模板和脉冲当量完成八轴 Trace 延迟标定。
控制器保存“发出参考命令前刚读取到的 Trace 序号—参考位置”历史；收到序号为
`S` 的反馈时，按该轴标定延迟 `tau_i` 查询 `S-tau_i/T_trace` 对应的历史参考位置，
线性插值后计算延迟对齐误差。跟随误差保护以及以后启用的 PID 都使用该对齐误差，
避免把固定采样/执行相位差误判成控制效果差；静态回归偏置 `b` 仅作诊断，不自动
从位置误差中扣除。该历史只用于误差计算，不改变 Newmark 固定步长、主机控制
格点和当前速度命令的生成。八轴共享一组 `Kff/Kp/Ki/Kd` 与限幅参数，但保留八份
积分和微分状态。轴速超过执行能力时仅对超限轴独立截断，其余轴命令保持不变；
理想参考轨迹不随限幅缩放，限幅造成的偏差由延迟对齐跟随误差保护检出并停止
试验。不对每周期速度命令增量施加八轴公共比例加速度限制，以免改变 Newmark
纯惯性模型的时间响应和等效质量。在线变速时间仅保留为板卡接口参数，并应设置
为不大于一个控制周期。

### 5.4 虚拟 CDPR 运动学一致性

阶段 B 中八个电机尚未连接绞盘和绳索，不能用实物平台验证运动，因此增加一条
只用于诊断的“虚拟 CDPR”链：

```text
固定初始位姿 q0
→ 逆运动学得到初始绳长 L0
→ 启动时锁存八轴 Trace 初始位置 θ0
→ Trace 实际电机位置 θact
→ 按临时方向、传动和绞盘模型换算虚拟实际绳长 Lact
→ ForwardKinematicsSolver
→ 虚拟实际末端位姿 qvirtual
```

比较量包括：

- Newmark 期望位姿与 `qvirtual` 的平移、姿态误差；
- 期望绳长与虚拟实际绳长误差；
- 八轴期望位置与 Trace 实际位置误差；
- 正运动学方程残差、有效方程数和收敛状态。

工程已经具备 `CompensatedCableKinematics` 和独立的
`ForwardKinematicsSolver`。改造时应先用现有模板参数完成逆运动学/正运动学
往返校验，再直接复用，不能在力交互控制器中另写一份运动学算法。

高频控制线程只完成控制所需的逆运动学、八轴闭环和轻量有效性检查。正运动学
求解不作为速度命令下发的前置条件：完整 Trace 数据进入异步记录队列，UI线程
按 5 Hz 使用现有 `ForwardKinematicsSolver` 计算虚拟位姿。阶段 B 会话结束后，
后台分析线程会重新读取自描述 CSV，按冻结的机架、八连接点和动态停车参数逐行
复算边界，并与在线记录的动作、余量、触发距离和连接点坐标比较，输出同目录
`*_boundary_analysis.json`。该分析不进入控制周期，也不会让迭代正运动学破坏
实时控制。

虚拟一致性良好只能说明软件数学链、轴映射、命令和反馈基本一致，不能证明真实
平台的绳索弹性、张力、摩擦、绞盘排绳和结构变形满足要求。

## 6. Trace 对象与硬件层改造

### 6.1 独立使用语义

阶段 B 已新增独立的 `ForceInteractionVelocity` Runtime Trace用途配置，读取八轴
实际位置、指令速度、实际速度及同帧状态字，并通过既有八轴批量速度入口下发命令，
不新增第二套板卡 API 链。阶段 C 接入真实F/T时，在该用途上增加六维力对象和
必要的过渡/运行会话语义。

六维力交互页新增独立的 `Trace延迟标定` 子页，并置于阶段 A 之前。标定使用
`PresetOnlineVelocity` 单轴 Trace 配置，按每轴 `±V1/±V2/±V3` 六段匀速运动采集
指令/实际位置和速度，以位置差—速度回归求 `tau` 与静态偏置 `b`，同时检查
R²、RMSE、正反向离散和帧序号连续性。结果按“G302原执行器/通用增量编码器8轴”
分别持久化；脉冲当量或 Trace 周期变化后自动标记失效，不能跨模板误用。

标定对象采用程序内部的逻辑绳索顺序，而不是直接使用控制卡轴号。G302映射为：
绳索1～8分别对应控制卡轴`4、5、7、6、0、1、3、2`及从站
`1005、1006、1008、1007、1001、1002、1004、1003`。UI必须使用从1开始的
绳索编号，并在同一选项和结果表中同时显示控制卡轴及从站，不能再向用户暴露
含义不明的0～7数字框。

不能沿用目前的 `EndpointRemoteRunning` 后再临时打开旧“力传感器”开关。现有
G302 模板已有的 force-sensor map 主要服务绳索张力通道，并非动平台六维 F/T，二者
必须使用不同的数据结构和配置名称。

### 6.2 六个对象描述符

增加 `FtWrenchTraceObjectDescriptor[6]`，每项至少包含：

- 物理分量；
- Trace 数据类型；
- 对象索引与子索引；
- 从站号；
- API 数据长度与帧内实际字节数；
- 数值编码/有符号性；
- 是否已配置。

六个力分量的Trace地址、类型、长度和比例已经确认。正式运行前仍必须做配置逐项
读回、帧宽核对、SampleCounter连续性检查和静止数据验证。解码层先按有符号32位
原始量读取，再显式乘以 `1e-4` 转成 N/N·m；比例写入描述符和运行记录，不能作为
无来源的隐藏常数。StatusCode按无符号32位保留原始值，在厂家位定义确认前只记录，
不据其未知位实施安全动作。

### 6.3 实时帧最小化

力交互运行帧只保留控制、记录和安全必需对象，当前首版为：

- 8 个实际位置；
- 8 个板卡指令速度；
- 8 个实际速度；
- 8 个状态字；
- 真实传感器阶段至少增加6个 F/T 通道和1个 SampleCounter；StatusCode和
  Temperature用于状态/预热诊断，能满足板卡对象数与帧宽时也放入同帧，否则先在
  预热专用profile采集；StatusCode位定义未知时只记录、不参与保护判定。

阶段B当前合计32个对象，阶段C运行profile预计至少39个，同时包含StatusCode和
Temperature时为41个。
板卡指令位置和反馈转矩不进入该profile；
板卡指令速度保留，用于核对主机下发值是否真正进入控制卡速度链。状态字属于同帧
安全对象，不作为控制量。

六个 F/T 值和八轴反馈必须来自同一个完整 Trace 帧，并共享逻辑帧序号。Sample
Counter用于识别传感器自身是否产生了新样本；计数不变的完整Trace帧保留在原始
记录中，但不重复进入判稳统计。真实采集丢帧依据Trace序号断裂、队列溢出和字段
完整性判断，不能再用单次Sample Counter是否严格`+1`替代。若板卡对象上限或帧宽
不允许39～41个对象，应先停止开发并重新选择信号集合，不能拆成两次
独立读取后伪装成同帧。

### 6.4 复合硬件任务

将当前
`readRuntimeTraceAndMotorVelBatchFastEndpointRemote()` 的通用部分抽为内部复合
任务：

```text
读取最新完整 Trace 批次
→ 验证 profile / 会话 / 帧序号 / FIFO / 新鲜度 / 状态字
→ 解码 8 轴反馈与 6 维力
→ 校验准备好的速度命令尚未过期
→ 一次批量执行 8 轴在线速度命令
```

遥控和力交互分别使用各自的会话令牌及准入 profile，避免一个模式错误接受另一
模式的缓存帧或待提交命令。

## 7. 周期和时间对齐

### 7.1 三种时间必须区分

- `T_bus`：通过 `nmc_get_cycletime()` 读回的 EtherCAT 总线周期；
- `T_trace`：`T_bus × dmc_trace_get_config()` 读回倍数；当前目标配置为
  500 μs，但代码不得用字面量 500 代替读回值；
- `T_c`：六维力动力学、逆运动学、八轴 PID 和命令更新的总体控制周期。

“Trace 与总体控制周期对齐”定义为：

```text
T_c = N · T_trace，N 为正整数
```

二者不要求数值相等。若 `T_trace=500 μs`，则 1、2、5、10、20 ms 控制周期
分别对应 2、4、10、20、40 个 Trace 帧。启动前必须按实际读回值校验整除关系。

### 7.2 时间主线

延续现有末端遥控架构，使用两条职责不同、但能够互相映射的时间线：

- **主机单调时钟**是控制调度主线：决定 Newmark、运动学、八轴 PID 和命令
  下发何时到期；
- **Trace 逻辑序号**是传感器与电机反馈采样主线：用于确认新帧、检测丢帧、
  防止重复消费，并保证六维力和八轴反馈来自同一帧。

`HardwareInterface` 已把板卡 Trace 逻辑序号按读回的采样周期映射到主机单调
时间，并在 `RuntimeTraceSnapshot` 中提供帧序号、帧龄、完整性和映射时间。阶段 B
首版直接消费该快照，不在上层重复猜测帧宽或重新构造时间戳。启动过程为：

1. 切换力交互 Trace profile 后清空 FIFO；
2. 取得第一帧可靠同帧数据，建立
   `(traceAnchorSequence, hostAnchorMonotonicUs)`；
3. 主机控制格点按
   `hostDueTime(k) = hostControlStartUs + k·T_c` 推进；
4. Trace 帧的逻辑采样时刻按下式映射到同一主机单调时间域：

   ```text
   traceTime(seq) = hostAnchorMonotonicUs
                  + (seq-traceAnchorSequence)·T_trace
   ```

5. 每个到期控制周期消费最新可靠的完整 Trace 数据，用逻辑序号检查该帧是否
   更新；实机链把期望状态按主机/模型运行时间写入历史。后续仅在误差诊断时，
   通过启动锚点把 Trace 序号映射为运行时间，再扣除各轴标定延迟查询历史参考；
6. 力样本 `W_k` 在对应模型区间内按 ZOH 保持，不查询或插值尚未取得的未来
   Trace 样本。

Trace 序号不直接决定“何时调用速度 API”，也不替代主机周期调度。主机定时器
只负责唤醒，真正的迟到量由当前单调时间与 `hostDueTime(k)` 比较得到，不能用
“回调次数 × 设置周期”伪造已经流逝的时间。

### 7.3 实际执行周期超出预设周期

每周期同时记录：

- 计划控制格点；
- 实际进入控制线程的主机时间；
- 最新 Trace 序号与帧龄；
- 本周期经过的 Trace 帧数；
- Trace 读取、Newmark、运动学、PID、API 和完整周期耗时。

当实际回调晚到时，由主机单调时钟计算实际经过时间和应到达的模型格点；Trace
序号只核对反馈是否正常产生，不驱动 Newmark。阶段 B 以及后续所有实机力交互
阶段采用相同处理：补齐固定 `T_c` 的数学积分子步，但每次只提交一组最新硬件
命令，绝不突发补发已经过期的速度命令：

- 尚未到达下一主机控制格点：不重复推进 Newmark；
- 正常到期且取得新鲜同帧 Trace：以固定 `T_c` 推进一步并下发一组速度；
- 晚到若干控制格点：用当前已取得的因果力样本按 ZOH 补算对应数量的 Newmark
  固定子步，完成后仅下发最新速度；
- 单次待补子步超过上限、Trace 序号异常或帧龄超限：认定实时链失效并安全停止。

Newmark 步长始终是冻结的总体控制周期 `T_c`。不能因为某次 Windows/Qt 调度
迟到，就把一个很大的实际回调间隔直接作为单次 Newmark 步长；也不能在恢复后
连续突发下发多组过期速度。阶段 A 仍按确定的离线步数运行；从阶段 B 到最终
六维力交互实机实验，统一使用“主机单调时钟推进模型、Trace 映射反馈时刻、
标定延迟只修正误差”的时间体系。

运行 CSV 从 v9 起增加 `model_elapsed_s`、`model_lag_us` 和
`integration_steps`，用于直接验证模型时间未随调度漏周期持续落后。

### 7.4 消除 500 μs 硬编码的范围

修改时应替换遥控准入代码中类似
`traceSamplePeriodUs == 500` 的字面量判断，改为与本次会话读回并冻结的
`expectedTraceSamplePeriodUs` 比较。这不是要求改变板卡当前 500 μs 设置，而是
避免代码把配置值、实测值和控制周期混为一谈。

## 8. 真实 F/T 的预热与零漂

真实模式从 Trace profile 配置成功后即可持续采样、显示和异步记录，但在零漂
确认前不得送入 Newmark。正常路径的最短预热时间设为15分钟。软件无法
可靠获知传感器真实通电时刻，因此默认从本软件首次收到有效SampleCounter时开始
计时。对于传感器在程序启动前已经通电的情况，提供“传感器已提前预热”选项；
勾选后进入缩短确认路径，但仍必须由软件连续采集至少3分钟并通过全部稳定性检查，
不能无数据直接跳过。状态为：

```text
未配置 → Trace待验证 → 正常预热15 min / 提前通电观察3 min → 候选稳定累计
       ↘ 轻微越限时暂停（最多1 s） ↗                         → 零漂已确认 → 力交互就绪
```

- UI将该选项命名为“传感器已提前预热（仍需观察3 min）”，避免让操作者误认为
  可以完全跳过采集；切换该选项会重新开始本次观察计时；
- 正常15分钟或缩短3分钟达到下限都只是必要条件，不能代替判稳；期间持续记录六维原始值、
  Sample Counter和温度，用于观察零漂随时间/温度的变化；
- 自动稳定判定在连续滑动窗口上分别计算六通道均值、标准差、均值变化率、
  峰峰值和有效帧率。Trace序号断裂、后台队列溢出和PDO字段不完整才计为采集
  异常；Sample Counter不变表示传感器本周期未更新，单独记录且不重复加入统计窗，
  不再把不同相采样形成的“保持一帧、随后追赶”误算成拒绝和缺样；
- 候选判稳采用带宽限的累计状态机：达到正常阈值后累计10秒；统计量轻微越限但
  未超过阈值的1.2倍时暂停累计，1秒内恢复则从原累计时间继续；持续越限超过1秒
  或任一统计量超过1.2倍阈值时才清零。Trace数据超时、有效率不足等数据链异常
  不使用宽限，立即撤销候选。UI显示最严重的通道、指标、当前值和两级阈值，日志
  仅在采集、持续确认、暂停、撤销、可取零和资格锁存之间切换时记录；
- 判稳状态只允许由F/T后台10 ms采集循环在取数后推进，启动、取零和停止也在该
  线程内获取同一单调时钟。GUI的Snapshot只读取缓存，不得调用判稳器或改变候选
  计时；跨线程排队导致查询时刻略早于最新样本时，负帧龄按0处理，不能误报超时；
- 阈值最终由本传感器空载静止预热数据统计确定。界面现有数值只是便于首轮采集
  和检查计算链的调试初值；未勾选“判稳阈值已由实测数据确认”时，即使数值判稳
  通过也不能取得阶段C准入。建议至少完成3次冷启动全预热记录，以稳定段噪声
  统计量的高分位数乘安全系数形成正式初值；
- 当前不自动确认零漂；人工确认前必须同时满足所选路径的最短时间、累计稳定保持
  时间、有效帧率和Trace数据链完整性；SampleCounter仅用于去除未更新的重复样本；
- 人工“确认当前零漂”不能覆盖判稳结论；只有最短观察、统计窗阈值和连续稳定
  保持全部通过后才允许确认。零漂仍取最近完整稳定窗口的均值，不取按钮瞬间单帧；
- 零漂确认成功时同时锁存“预热合格”资格。后续真实施力必然使空载滑窗指标波动，
  因此不再用实时 `stable` 撤销已取得的资格；运行中只持续检查PDO完整性、Trace时序、
  数据新鲜度和丢样。显式清除软件零点时一并撤销预热资格；
- “判稳阈值已由实测数据确认”在监测中仍可勾选，但它只是操作员的阈值
  准入声明，不兼任自动取零开关。当前流程在判稳完成后统一由操作员点击按钮确认零漂；
- 零漂在运行期间冻结，停止预热采集时保留；只有显式点击“清除软件零点”才使其失效。
  阶段C仍必须重新取得完整、连续且时序可信的F/T Trace；
- 零漂属于本次运行状态，写入记录文件但不自动覆盖固定安装配置。
- 零漂确认前若统计稳定性恶化，按上述暂停/撤销状态机处理；零漂确认后不再因真实
  施力导致的滑窗波动撤销资格。Sample Counter失效、Trace数据超时或数据链异常仍
  会阻止启动；运行中出现上述数据链异常则冻结力输入并进入受控停止，不能继续沿用
  陈旧力样本。

## 9. UI 调整方案

现已在 `mainwindow.ui` 中增加独立“六维力交互”页，子页依次为
“Trace延迟标定”“F/T传感器（阶段C准备）”“软件验证（阶段A）”和
“电机空转（阶段B）”；固定控件、分组和布局均保留在 `.ui`，C++ 只负责
参数读取、控制编排和状态刷新。后续页面继续按下列职责扩展，不把控件塞入
遥控页：

六维力交互专属的执行器模板应放在A/B/C/D子页签上方，由所有阶段共享：阶段A
不访问硬件，模板选择不参与阶段A数学通过判定；阶段B启动硬件会话时冻结模板与
脉冲当量，阶段C～D沿用该会话参数。该模板不得影响
PVT、末端遥控、转矩测试和原有力控页面。当前提供“G302原执行器”和“通用增量
编码器8轴”两项；后者按`180224/360 = 500.622222222 pulse/°`，约定
`1 unit=1°`，并在临时会话内部完成原圈单位软件限位到度单位的等价换算。

1. **输入**：模拟/真实选择，六分量常值、脉冲、正弦或公式；
2. **传感器**：六通道 Trace 映射状态、预热状态、稳定窗口、确认/清除零漂；
3. **安装**：`R_ES`、`r_ES_E`、方向约定及“未配置”提示；
4. **动力学与控制**：总体控制周期、质量惯量摘要、Newmark 参数、速度前馈和
   限幅；PID参数保留但默认关闭；
5. **状态**：主界面只显示当前工程值、去零值、预热进度、判稳/零点和数据链
   摘要；原始整数、PDO地址、统计量、计数器及逐帧诊断保存到日志和CSV；
6. **操作**：准备、启动、正常停止、急停。

页面还应提供“只计算”和“电机空转”两个明确模式：

- **只计算**：运行模拟力、Newmark、运动学和虚拟反馈，不调用雷赛运动 API；
- **电机空转**：使用真实八轴 Trace 反馈并下发八轴速度，但仍明确标注为虚拟
  CDPR 验证，不显示为实物平台控制已就绪。

安装参数和 Trace 对象可放入单独配置对话框，主页面只显示“未配置/已验证”和
摘要。运行期间冻结所有影响实时链的配置。阶段 A 页面只读显示当前实测
`r_ES` 和 `R_ES`，并明确模拟量按传感器原始值进入同一安装变换链。

### 阶段 C：真实 F/T 与八电机空载联调

阶段 C 的对象是“真实六维力输入下的八电机空载运动”。它不是第二套控制器，
而是把阶段 B 的 `SimulatedWrenchSource` 替换成经过准入的真实 F/T Trace 样本；
从力旋量变换开始，Newmark、逆运动学、八轴速度前馈、Trace 对齐、边界、停车、
记录和事后正运动学必须与阶段 B 共用同一实现。

#### C.1 已有基础

- 已按 `0x4000:00～0x4008:00` 建立 F/T 单独调试及八轴合并 profile，并逐项
  校验 `dmc_trace_get_config_object` 读回；
- `ForceInteractionVelocityWithFt` 能在一个 Trace 帧中提供八轴位置、速度、
  状态字以及 F/T 六维力、状态码、SampleCounter 和温度；
- 已实现 15/3 分钟预热、滑窗判稳、人工软件取零和原始 CSV；
- 运行内核已经具备阶段 B 的主机单调时钟调度、固定步长 Newmark 补算、八轴
  批量变速、延迟对齐跟随误差、绞盘行程和末端边界保护。

#### C.2 代码结构

`ForceInteractionRuntimeConfig` 增加显式输入源枚举：

- `Simulated`：阶段 B，使用现有模拟力配置；
- `RealFtTrace`：阶段 C，使用同一 Runtime Trace 快照内的 F/T 数据。

`ForceInteractionRuntimeControl` 仍是唯一运行状态机。阶段 C 不复制 Newmark、
运动学、PID/前馈或安全代码，只在每次进入动力学前完成真实样本适配：

1. 样本必须来自 `ForceInteractionVelocityWithFt` 对应的最新完整 Trace 帧；
2. 六个通道、状态码、SampleCounter、温度及 Trace 序号均有效；
3. 样本帧龄未超过冻结的 F/T 超时阈值；
4. 从工程量中减去准备阶段冻结的软件零漂；
5. 以传感器坐标系 S、传感器测量点为参考构造 `ForceInteractionWrenchSample`；
6. 经 `R_ES=I`、`r_ES_E=[0,0,0.32548]^T m` 换算到平台质心；
7. 仅对真实 F/T 的质心力旋量执行可配置一阶低通，并分别按三轴合力模长和
   三轴合力矩模长执行带迟滞的启动/释放门；模拟力路径不经过该调理；
8. “仅平动”模式在调理前清零质心三维力矩，确保力臂交叉力矩不会进入动力学；
9. 本次主机控制周期及其补算的 Newmark 子步均以调理后的样本 ZOH 保持，不插值或
   使用未来样本。

同一个 F/T SampleCounter 在少量控制循环中重复不立即报错，允许 ZOH；超过
F/T 新鲜度阈值仍没有新样本才判定输入失效。计数器倒退、无合法回绕解释的异常
跳变、状态码异常、非有限数或不完整帧均使本次试验失效并进入停机路径。

#### C.3 Trace 与线程所有权

- 预热页启动后，`FtSensorMonitoringService` 始终是 F/T 逐帧队列的唯一消费者，
  负责判稳、零点锁存和原始记录；GUI 只读取摘要；
- 阶段 C 运行时由 `ControlWorker` 每周期读取一次合并 Runtime Trace 快照并直接
  使用其中的最新 F/T 样本，不从预热队列二次取数；
- 运行期间后台服务仅消费控制线程已经解析入队的 F/T 样本，不再主动发起第二次
  Trace 读取，避免 HardwareThread 争用；
- 阶段 C 结束后恢复 F/T 单独调试 profile，预热监测、已锁存预热资格和软件零点
  继续有效，除非用户显式停止监测或清除零点。
- 每次重配 Runtime Trace 对象都会开启新的“Trace 帧纪元”：只清除旧帧序号连续性
  基准和旧最新样本，不清除预热计时、统计窗口、已锁存资格或软件零点。第一帧新
  profile 完整数据到达后重新建立准入，禁止将板卡重配导致的帧号归零误判为永久倒序。

控制指令、Newmark 模型时间和超时仍以主机单调时钟为主线；Trace 序号用于新帧
识别、同帧完整性和跟随误差离线/在线对齐，不能用“步数×周期”替代主机时间。

#### C.4 准入和配置冻结

“准备阶段 C”必须同时满足：

- 完整系统、控制卡和八轴已就绪，且没有其他运动任务；
- 当前为标准八轴/传感器从站 1009 拓扑；
- F/T 后台监测仍在运行，预热资格和软件零点已经锁存；
- 当前样本完整、新鲜、Trace 时序可信、未锁存丢帧且后台队列未丢样；
- 操作员已经确认判稳阈值；
- 合并 Trace 配置/读回成功，F/T 与八轴对象均来自同一帧；
- 当前执行器模板、脉冲当量、总线/Trace 周期及八轴延迟标定相互匹配；
- 初始位姿、刚体参数、运动学、八轴软件行程和物理工作空间有效。

准备成功后冻结输入源、软件零漂、安装变换、F/T 超时、低通截止频率、合力/合力矩
启动与释放阈值、质量惯量、初始位姿、
运动学、延迟、速度与安全参数。运行中改变界面值不影响本次会话。PID 仍保留但
固定关闭，阶段 C 首轮只验收开环速度前馈。

#### C.5 公共边界与停机

阶段 C 原样复用阶段 B 的边界体系：

- 八连接点几何硬边界；
- `v²/(2a)+附加安全余量` 动态停车边界；
- 固定急停线；
- Newmark 期望位姿、速度和加速度有效性；
- 八轴期望/Trace 实际绞盘相对行程；
- 同帧 0x6041 状态、八轴速度上限、延迟对齐跟随误差；
- Trace 新鲜度、完整性、丢帧和雷赛速度 API 返回值。

阶段 C 只新增 F/T 输入有效性保护，不定义另一套空间边界。用户停止或空载调试
最长时间到达时冻结力输入并协同减速；F/T 超时或状态异常使试验无效并协同减速，
若无法继续生成可信制动轨迹则升级八轴立即停止；驱动故障、API 失败、固定急停线
或硬边界越界直接立即停止。一旦进入停车，本次力交互不允许重新接力恢复。

#### C.6 UI 与运行记录

停止按钮明确显示“取消准备”，运行后才显示“协同减速停止”；立即停止按钮只有在
等待 Trace、运行或制动状态才启用，禁用时必须显示为灰色。公共周期、
执行器模板、速度/跟随误差、末端加速度及边界参数继续复用阶段 B 的现有控件，
避免两套同名参数漂移。

阶段 C 复用 `ForceInteractionRunRecorder`，元数据标记 `stage_c` 和真实 F/T；
逐周期记录原始工程量、冻结零漂、去零力、状态码、SampleCounter、温度、F/T
帧龄、未滤波质心力旋量、滤波力旋量、迟滞门状态和最终送入 Newmark 的力旋量，
以及阶段 B 已有的 Newmark 状态、八轴参考/命令/Trace、边界与
耗时。运行结束继续使用公共“一键计算与评估”，以同帧八轴 Trace 位置离线正解
虚拟实际位姿，并与按 Trace 时刻对齐的 Newmark 期望位姿比较。

真实 F/T 调理默认值为：一阶低通 10 Hz，合力启动/释放阈值 0.30/0.15 N，
合力矩启动/释放阈值 0.010/0.005 N·m。阈值使用向量模长是为了不偏袒某一轴方向；
启动值大于释放值形成迟滞，避免零点噪声令输入在相邻周期反复开关。它不是按
“相邻两帧差值”触发：差分会放大噪声，而且恒定接触力在建立后差值接近零，却仍应
持续产生惯性加速度。默认值只是首轮空转调试值，后续应根据去零后的实测静止噪声
和最小有效接触力调整。

**测试方法与通过条件**

- 至少完成3次冷启动、每次不少于30分钟的空载静止采集，验证15分钟默认门槛并
  确定噪声、均值漂移、
  峰峰值、温度相关性和稳定阈值；
- 施加已知方向的力，核对通道顺序、符号、比例和单位；
- 使用已知力臂检查力矩和平移力产生的交叉项；
- Trace 帧宽、序号、有效率和帧龄通过后，才允许真实力输入驱动空载电机；
- 空载子试验重复阶段 B 的虚拟运动学一致性分析，确认换成真实力源后控制周期、
  停机和八轴映射没有退化。

**实施顺序**

1. 扩展公共运行配置、反馈、状态和记录结构，但保持阶段 B 默认行为不变；
2. 增加真实 F/T 样本适配与可单元测试的校验/ZOH逻辑；
3. 让后台预热服务支持阶段 C 运行态的“仅消费、不主动读 Trace”；
4. 接入 `ControlWorker` 合并 Trace、profile 切换和通用停机恢复；
5. 在 `.ui` 中增加阶段 C 子页，在 `MainWindow` 中实现准入冻结和操作入口；
6. 构建并执行数学/配置静态测试，确认阶段 B 模拟力路径未回归；
7. 实机先用零力和极短时低速验证，再施加单方向小力，最后运行运动后一键评估。

## 14. 后续实物阶段仍需用户提供的信息

真实 F/T 接入前需要：

1. 实机复核传感器三轴与平台局部三轴同向，即 `R_ES=I`；
2. 确认实测 `r_ES_E=[0,0,0.32548]^T m` 的端点就是传感器输出力矩所采用的
   测量参考原点；
3. 通过已知方向加载复核当前 `wrenchReactionSign=+1` 与传感器输出正负方向；
4. 程序接入后生成的`0x4000～0x4008`完整Trace配置读回与帧宽诊断记录；
5. 静止及已知方向加载试验，用于核对六通道顺序、符号和`1e-4`比例；
6. 至少3次冷启动、每次30分钟以上的静止预热原始数据，用于验证15分钟门槛并
   确定稳定判定阈值；
7. StatusCode各位的厂家定义及正常/故障样例值。

这些项目中的实测证据不足不妨碍阶段 A、B，也不妨碍以严格准入、小力、空转方式
调试阶段 C；但必须阻止阶段 C 被标记为“已验收”，更不能据此进入阶段 D 实机收绳。
